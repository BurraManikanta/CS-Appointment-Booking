# AI usage record

## Engineering activity

AI assistance was used to implement and document the appointment-booking service and to design focused tests from the supplied requirements.

## Prompt

The exact final instruction in the request was: “You now have the complete roadmap. Implement it step by step exactly as listed above.”

The preceding request supplied the detailed checklist for an appointment service, including UTC `Instant` times, positive durations, same-provider active-appointment conflict checks, half-open intervals, cancellation results, tests, and the required documentation.

For the Gradle migration, the prompt was: “replace the code with gradle version”.

For the UI and API, the prompt was: “Implement a small UI,that calls these endpoints and it should be short and quicker to implement”.

## AI reply summary

The AI first implemented a Java 17 service with an in-memory active-appointments-by-provider map, an ID lookup map, synchronized booking/cancellation, custom validation/conflict exceptions, a cancellation-result enum, JUnit 5 tests, and documentation. In response to the migration prompt, it replaced the Maven build configuration and Maven instructions with Gradle configuration and instructions, and generated a Gradle wrapper.

For the UI request, the AI added a small static HTML page and a lightweight local Java HTTP server exposing booking and cancellation endpoints, keeping the existing appointment service as the source of booking rules.

## Decision

Accepted with implementation choices made explicit: appointment IDs are generated by the service; blank provider/cancellation IDs are rejected; end-time overflow is validated before store changes; and the active appointment store is checked with a package-private test counter. The interval overlap condition uses strict comparisons, so adjacent appointments are allowed.

## Verification

The implementation includes automated tests for successful booking, overlaps, adjacency, provider isolation, cancellation and rebooking, missing/already-cancelled cancellation, invalid/null/blank inputs, and end-time overflow. `.\gradlew.bat test` passes. Live checks confirmed the UI returns HTTP 200, booking and cancellation work, and a non-UTC timestamp is rejected with HTTP 400.
